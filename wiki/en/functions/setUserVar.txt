<dash>
name: $setUserVar
desc: Remembers a value for one member inside one server.
category: Variables

<block type="text" title="How does the command work?">
text: $setUserVar saves a value against a name you choose and a member you pick, so a score, a strike count or a last-seen note can sit next to that person and nowhere else. With just a name and a value it files the entry under whoever ran the command, in the server they typed it in. Add a user ID or a server ID as the third or fourth part and the value is written somewhere else entirely.
</block>

<block type="list" title="How to use it in the app">
item: Create the variable first in the Variables tab
item: Open the Commands tab
item: Tap + to start a new command
item: Give it a name in the Name field
item: Set the Prefix field to !points
item: Paste the code below into the editor
item: Tap Save
</block>

<block type="code" title="Syntax">
text: $setUserVar[name; value; (user_id); (guild_id)]
</block>

<block type="code" title="Ready-to-copy Example">
text: $setUserVar[points; 10; 123456789012345678; 987654321012345678]
</block>

<block type="callout" kind="important">
text: The value does get saved even on the first run, but if the name is not in the Variables tab yet the command still stops with an error. Create the variable there first and the save goes through quietly from then on.
</block>
</dash>

<details>
syntax: $setUserVar[name; value; (user_id); (guild_id)]
param: name|text|Required|The name the value is filed under
param: value|text|Required|What to remember
param: userID|snowflake|Optional|Which member it belongs to. Leave it out to use the person who ran the command.
param: guildID|snowflake|Optional|Which server it belongs to. Leave it out to use the current one.
</details>
