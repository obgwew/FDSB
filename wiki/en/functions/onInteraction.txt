<dash>
name: $onInteraction
desc: Runs your script when somebody clicks a button or picks an option from a menu.
category: Event

<block type="text" title="How does the event work?">
text: Give a command the Prefix field $onInteraction and the app marks it as an Event for you. From then on every button press and every choice made in one of your menus runs the lines underneath, with the person who pressed and the ID of the component they touched both on hand. Leave the brackets off and the event covers every component on every message, or name a single ID inside them and only that one button or menu wakes the command up.
</block>

<block type="list" title="How to use it in the app">
item: Open the Commands tab
item: Tap + to start a new command
item: Give it a name in the Name field
item: Set the Prefix field to $onInteraction
item: The app marks it as an Event for you
item: Paste the code below into the editor
item: Tap Save
</block>

<block type="code" title="Syntax">
text: #PREFIX:$onInteraction
text: #PREFIX:$onInteraction[button_custom_id]
</block>

<block type="code" title="Ready-to-copy Example">
text: #PREFIX:$onInteraction[confirm_btn]
text:  sendMessage[You clicked the confirm button!]
</block>

<block type="callout" kind="note">
text: The ID you put in the brackets is the one you chose when you built the button or menu. Capital letters are ignored on both sides, so confirm_btn and CONFIRM_BTN wake the same command.
</block>

<block type="callout" kind="important">
text: No typed message sits behind a click, so $authorID, $authorName, $mention and $customID are the pieces of information worth reaching for. The press is already answered by the time your lines start, so a slow command will not make the button look frozen.
</block>
</dash>

<details>
syntax: $onInteraction[(custom_id)]
param: customID|text|Optional|Leave it empty to catch every component, or name the one ID you want to listen for
</details>
