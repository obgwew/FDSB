<dash>
name: $addButton
desc: Puts a tappable button under the message your command sends.
category: Components

<block type="text" title="How does the command work?">
text: Each call adds one button, and you decide what it looks like and where it sits. Give it a label and a colour and it appears under the message once your command posts it. A button in any style other than link carries an ID of your choosing, which is how you recognise the press later inside an $onInteraction event; a link button instead just opens the address you hand it.
</block>

<block type="list" title="How to use it in the app">
item: Open the Commands tab
item: Tap + to start a new command
item: Give it a name in the Name field
item: Set the Prefix field to !menu
item: Paste the code below into the editor
item: Tap Save
</block>

<block type="code" title="Syntax">
text: $addButton[newLine; ID/URL; label; style; (disabled; emoji; messageID)]
</block>

<block type="code" title="Ready-to-copy Example">
text: $addButton[no; btn_confirm; Confirm; success]
</block>

<block type="options" title="Button styles (style)">
option: primary|Blue button
option: secondary|Grey button
option: success|Green button
option: danger|Red button
option: link|Opens a web address instead of firing an event
</block>

<block type="callout" kind="note">
text: Choose link and the second part has to be a full address starting with http:// or https://. Every other style wants a short ID instead, and no two buttons on the same message may share one.
</block>

<block type="callout" kind="warning">
text: A message can carry 25 buttons at most, five to a row and five rows deep. When a row fills up the next button drops onto a fresh one by itself, and running out of room stops the command with an error.
</block>

<block type="callout" kind="important">
text: Fill in the last part with the ID of a message the bot already sent and the button lands on that message instead of the next one, which is how you grow a menu after the fact.
</block>
</dash>

<details>
syntax: $addButton[newLine; ID/URL; label; style; (disabled; emoji; messageID)]
param: newLine|yes/no|Required|yes starts a fresh row, no tucks it in beside the last button
param: ID/URL|text|Required|The short ID your event matches on, or a full address when style is link
param: label|text|Emptiable|The words shown on the button
param: style|text|Required|primary / secondary / success / danger / link
param: disabled|yes/no|Optional|yes greys the button out so it cannot be pressed (default: no)
param: emoji|text|Optional|An emoji to show on the button
param: messageID|snowflake|Optional|Which message the bot already sent to add the button to instead
</details>
