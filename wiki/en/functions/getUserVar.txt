<dash>
name: $getUserVar
desc: Reads back the value one member keeps for a variable name.
category: Variables

<block type="text" title="How does the command work?">
text: Every member gets their own slot under the same variable name, and this is what reads it. With just a name you get the slot belonging to whoever typed the command; add a member ID and you read theirs instead. While that slot is still empty the shared value from the Variables tab is handed back, so nobody is ever left with nothing at all.
</block>

<block type="list" title="How to use it in the app">
item: Create the variable first in the Variables tab
item: Open the Commands tab
item: Tap + to start a new command
item: Give it a name in the Name field
item: Set the Prefix field to !profile
item: Write your script in the editor
item: Paste the line below wherever you need it
item: Tap Save
</block>

<block type="code" title="Syntax">
text: $getUserVar[name; (user_id); (guild_id)]
</block>

<block type="code" title="Ready-to-copy Example">
text: $getUserVar[points; 123456789012345678]
</block>

<block type="callout" kind="important">
text: Name a variable that was never created in the Variables tab and the bot adds an empty one, warns you about it and stops your command. Set the variable up first.
</block>

<block type="callout" kind="note">
text: The member you get by default is whoever typed the command, and the server defaults to the one it ran in. Nothing reaches the chat unless you leave the line on its own.
</block>
</dash>

<details>
syntax: $getUserVar[name; (user_id); (guild_id)]
param: name|text|Required|Which variable to read
param: userID|text|Optional|Whose own value to read; leave empty for the person who typed the command
param: guildID|text|Optional|Which server to look in; leave empty for the server the command ran in
</details>
