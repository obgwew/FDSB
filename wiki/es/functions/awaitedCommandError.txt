<dash>
name: $awaitedCommandError
desc: Se ejecuta cuando la respuesta tras $awaitInput no coincide con el filtro que estableciste.
category: Evento

<block type="text" title="¿Cómo funciona el evento?">
text: Este es el compañero de $awaitedCommand. Dale el campo Prefijo $awaitedCommandError[name], usando el mismo nombre de espera, y se ejecuta solo cuando llega una respuesta, existe un script $awaitedCommand con ese nombre, pero la respuesta no pasa su filtro.
text: Un uso clásico es una pregunta de sí o no: el script de espera normal maneja las palabras aceptadas, mientras que este señala amablemente que no se entendió la respuesta. El texto rechazado es el mensaje detrás del script, así que $message sigue conteniendo lo que se escribió.
</block>

<block type="list" title="Cómo usarlo en la aplicación">
item: Abre la pestaña de comandos
item: Toca + para crear un comando nuevo
item: Ponle un nombre en el campo Nombre
item: Establece el campo Prefijo en $awaitedCommandError[confirm]
item: La aplicación lo marca como evento por ti
item: Pega el código de abajo en el editor
item: Toca Guardar
</block>

<block type="code" title="Sintaxis">
text: #PREFIX:$awaitedCommandError[name]
</block>

<block type="code" title="Ejemplo listo para copiar">
text: #PREFIX:$awaitedCommandError[confirm]
text: $sendMessage[Please answer with yes or no.]
text: $awaitInput[confirm]
</block>

<block type="callout" kind="note">
text: El script de error no tiene filtro propio; cualquier respuesta que falle el filtro del $awaitedCommand correspondiente lo despierta. Si no existe ningún script $awaitedCommand para ese nombre, aquí tampoco pasa nada, así que crea siempre también el script normal.
</block>

<block type="callout" kind="warning">
text: La espera la consume la respuesta aunque no coincida. Para preguntar de nuevo, ejecuta $awaitInput con el mismo nombre una vez más, como hace el ejemplo.
</block>
</dash>

<details>
syntax: $awaitedCommandError[waitName]
param: waitName|text|Obligatorio|El nombre usado por las líneas $awaitInput y $awaitedCommand correspondientes
</details>
